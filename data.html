Every file carries a provenance group recording the parameters, the code revision and the build time that produced it, and the release ships a MANIFEST.json of SHA-256 checksums. When you need to know exactly what a file is, read its provenance rather than any documentation, including this page.

Using it

Predict a statistic anywhere in parameter space

The emulator reproduces the model's four summary statistics in milliseconds, with no simulation and no modelling code — only numpy and h5py: 

import sys; sys.path.insert(0, "01_emulator")
from predict import load, predict

emu = load("01_emulator/emulator_qlf.hdf5")
print(emu.param_names)     # the six parameters, in order
print(emu.param_ranges)    # the box it is valid in

y = predict(emu, [-1.2355, 0.8327, 0.5075, 5.8947, -6.4694, 0.5056])
# y[0] is log10(QLF), shape (n_redshift, n_Lbins); the grids are in emu.axes

Outside emu.param_ranges the Gaussian process extrapolates and will return a smooth, confident, wrong answer. Check the box.

Read the posteriors

import emcee
r = emcee.backends.HDFBackend("02_posterior/chain_qlf_cerdf_corr.hdf5", read_only=True)

Query the quasar catalogue

One file per redshift. The weight column is a statistical weight: use it in every histogram and every number density, or the counts are wrong. 

import h5py, numpy as np
with h5py.File("03_catalogue/qso_catalogue_z06.14.hdf5") as f:
    M_BH   = f["M_BH"][:]            # solar masses
    L_bol  = f["L_bol_Lsun"][:]      # solar luminosities, NOT erg/s
    weight = f["weight"][:]
    print(dict(f["units"].attrs))

Luminosities are stored in solar units on purpose: in erg s\(^{-1}\) a bright quasar overflows 32-bit floats, and storing them as 64-bit would double the size of the largest part of the release for no gain. The conversion factor is in the units group.

What the statistics are over

The four statistics are not all over the same population, and the difference matters more than it sounds:

  • The luminosity function and the black hole mass function are over the whole population. The luminosity function applies no cut — faint objects simply fall below the lowest bin, and the mass function includes every black hole, most of which are not accreting at all.
  • The Eddington-ratio distribution and the host halo mass function are conditioned on luminosity by construction: one distribution per luminosity threshold.

So the catalogue — which contains bright quasars only — can reproduce the last two but not the first two. Histogramming its black hole masses gives the active mass function, which at \(z=0\) differs from the total by a median of about 1.1 dex, and by nearly 3 dex at the low-mass end.

Before you use it

The model has known failures, and they are documented rather than buried: the conditional Eddington-ratio distribution comes out 1.5–2× too broad, the faint end of the luminosity function is under-reproduced, and quasar clustering at \(z\approx4\) shows a residual discrepancy. Read the limitations before quoting a prediction.
